02 — How it works

You speak. Your agent plans.
The CLI executes.

The person delegates intent in natural language. The calling agent owns judgment and presentation. SkillRoster owns deterministic discovery, validation, mutation, and recovery — a binary with no model calls inside.

01

Scan & report

A read-only scan persists an immutable snapshot of every skill, placement, link, fingerprint, and usage signal. Seven categories of findings, each traced to concrete evidence.

skillroster scan --summary --json
02

Plan

The agent submits declarative target states against snapshot and evidence IDs. The CLI validates ownership, conflicts, and fingerprints, then stores an immutable preview. Raw filesystem operations are rejected.

skillroster plan --stdin --json
03

Apply & undo

One confirmation applies the whole approved scope. Drift fails closed, every mutation writes a receipt, and undo restores the original tree — byte for byte.

skillroster undo <receipt-id> --json

EVIDENCE BEFORE CHANGE

No hunches, only traces

Findings distinguish installed, exposed, invoked, useful, duplicated, stale, and unsafe. Missing evidence is never proof that a skill is useless.

LOCAL-FIRST

Your machine is the backend

One SQLite database in ~/.skillroster. Sessions parsed read-only in place; raw prompts never copied. No account, no telemetry.

ONE-CONFIRMATION APPLY

Approve once, not nine times

The agent prepares and explains a complete plan; the person approves the whole scope once. No per-operation prompts, no silent changes.

04 — Command surface

A small grammar,
deliberately kept small.

Every JSON response shares one versioned envelope with typed suggested actions. Agents consume structure — never scraped prose.

scan --summary --json Discover skills and persist an immutable snapshot. read-only
report --finding <id> --json Seven analysis categories with paged evidence drill-down. read-only
find <task> --load --json Rank routable skills; load one verified SKILL.md identity. read-only
plan --stdin --json Validate an agent-authored plan into an immutable preview. read-only
apply <plan-id> --json Execute one approved scope, journaled, receipt-bounded. mutating
undo <receipt-id> --json Reverse exactly the changes recorded by one receipt. mutating
setup --json Preview bootstrap skill installation for detected agents. read-only
source-root confirm · inspect · revoke Exact, fail-closed local read permissions for escaping links. mutating
lifecycle inspect · export · purge Retention, exclusion, export, and deletion of local state. mutating
status --json Storage, retention, pending plans, and recovery boundary. read-only
05 — Safety model

Fail closed,
by default.

Governance you cannot talk your way past. The rules below live in the plan validator and the storage layer — not in a prompt.

DRIFT REFUSAL

Fingerprints or nothing

Apply revalidates every path, link, and fingerprint before mutating. A plan created by an older binary cannot bypass the complete-fingerprint boundary.

TRUST IS EXPLICIT

No inferred permission

Escaping links stay untrusted until one exact directory is confirmed. No parent, sibling, wildcard, or alias permission is ever inferred — replaced or retargeted roots fail closed.

RECOVERY BLOCKING

Unresolved means stop

While any receipt requires recovery, new writes are blocked. Undo is bounded to its receipt and refuses ambiguous restoration. Canonical deletion sits outside normal apply.

THERE IS NO --force --yes --auto-fix — BY DESIGN.
